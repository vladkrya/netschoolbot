# Бот «Сетевого города» 🎓

Telegram-бот и PWA для «Сетевого города. Образование»: уведомления о новых
оценках, их изменениях и удалениях, домашние задания, расписание, школьная
почта и статистика.

Домен: **https://ns.ikrya.ru** (на vdsru, без Cloudflare). После инцидента Yandex Cloud 08.10.2026 основной адрес перенесён на сервер бота; `ns2.ikrya.ru` остаётся резервным. Прежний `netschool.ikrya.ru` работает для уже открытых ссылок и установленных PWA.

## Что это за версия

Проект переписан с нуля. Прежняя версия работала, но её нельзя было чинить:
17 000 строк без единого теста, две независимые реализации клиента
«Сетевого города» (одна для бота, другая для мини-приложения), JSON-файлы
как база данных под записью из двух потоков, 280 перехватов `except
Exception`, гасивших ошибки на месте возникновения, и функция проверки
оценок на 568 строк.

Что изменилось по существу:

| | Было | Стало |
|---|---|---|
| Клиент «Сетевого города» | две реализации, расходились в поведении | одна, общий пул сессий |
| Процессы | бот в asyncio + Flask/eventlet в потоке | один процесс, один event loop |
| Хранилище | JSON-файлы и общий словарь в памяти | SQLite с транзакциями и WAL |
| Запрос из PWA | `asyncio.run()` на каждый HTTP-запрос | общий event loop, сессии переиспользуются |
| Вёрстка | 6400 строк HTML/CSS/JS в Python-строках | шаблоны и статика отдельными файлами |
| Тесты | нет | ~590 |
| Веб-панель | терминал с PTY и файловый менеджер с корнем `/` | убрана |

Выстраданные обходы чужих багов перенесены как есть — это знание о том, как
себя ведёт «Сетевой город» и ЕСИА, а не архитектура: приём `202` на верный
код подтверждения, пропуск шага `MAX_QUIZ`, протухающая пометка «хосту нужен
прокси» вместо вечного Tor, повышенный таймаут прямых запросов.

## Структура

```
app/
├── main.py              точка входа: бот и веб в одном процессе
├── settings.py          конфигурация с проверкой на старте
├── context.py           сборка зависимостей
├── domain/              модели, записи дневника, тексты — без внешних зависимостей
│   ├── models.py        пользователь, фильтры, тихие часы
│   ├── records.py       оценки, задания и их идентичность
│   └── formatting.py    всё, что видит человек
├── db/                  SQLite: схема, миграции, репозитории, перенос из JSON
├── netschool/           «Сетевой город»: пул сессий, сервис, ошибки, патчи
├── notifications/       diff.py — чистое сравнение оценок; watcher.py — цикл
├── bot/                 aiogram: обработчики, клавиатуры, доставка
└── web/                 aiohttp: API, шаблоны, статика, push
    ├── templates/       разметка страницы
    └── static/js/       модули экранов: дневник, оценки, ДЗ,
                         почта, калькулятор, профиль
tests/                   тесты (python -m pytest)
```

Ключевое разделение: `notifications/diff.py` не знает ни про сеть, ни про
Telegram, ни про базу. Именно поэтому логику уведомлений — самую
баго­опасную часть проекта — стало возможно проверять.

## Установка

```bash
git clone https://git.dc09.xyz/ikrya/netschoolbot.git /opt/netschoolbot
cd /opt/netschoolbot
python3 -m venv venv && ./venv/bin/pip install -r requirements.txt -c constraints.txt
cp .env.example .env && nano .env

./venv/bin/python -m app.main
```

### Перенос данных из старой версии

При первом запуске перенос выполняется сам: если база пуста, а рядом лежат
файлы старой версии (`data/netschool_users/netschool_users.json`), они
переносятся автоматически. Повторно ничего не произойдёт.

Запустить вручную, например с копии данных другого сервера:

```bash
./venv/bin/python -m app.main --import-legacy /opt/netschoolbot-old/data
```

Переносятся пользователи с настройками, сессии, постоянные ссылки на PWA
и отметки о прочитанных письмах. Состояние слежения за оценками не
переносится: старые ключи считались по другим правилам. Вместо этого
первая проверка каждого перенесённого пользователя проходит молча и
пересобирает состояние — иначе человек получил бы весь журнал за год
одним залпом.

### Выкладка

GitHub больше не используется, выкладка — скриптом с машины разработчика:

```bash
deploy/deploy.sh
```

Он прогоняет тесты (упавшие — выкладки нет), пушит `main` в `dc09` и на
сервере: снимает копию базы, переключает код, ставит зависимости по
`constraints.txt`, обновляет юниты systemd, перезапускает службу и ждёт
`200` от `/health`. Если что-то упало после переключения — откат на
прежний коммит, а если миграция успела изменить схему, то и база из
снятой копии. Итог приходит админу в Telegram с названием упавшего шага
и хвостом журнала.

### Резервные копии

`netschoolbot-backup.timer` раз в час снимает копию базы в `data/backups/`
(online backup SQLite — корректно при работающем боте) и проверяет её
(`integrity_check`, версия схемы, число пользователей). Хранятся 24 последние
копии и ещё по одной (последней) за каждые из 20 последних суток.
Перед каждой выкладкой — отдельная копия `netschoolbot-predeploy-*`, их
выкладка держит 10. Сбой копии — сообщение админу (`netschoolbot-alert@`).

```bash
./venv/bin/python -m app.tools.backup                 # копия сейчас
./venv/bin/python -m app.tools.backup --verify FILE   # проверить копию
systemctl stop netschoolbot && ./venv/bin/python -m app.tools.backup --restore FILE
```

Вернуть одному пользователю его отметки ДЗ, историю оценок, заметки и
настройки приложения — без остановки бота и без отката остальных:

```bash
./venv/bin/python -m app.tools.restore_user --from FILE --user TELEGRAM_ID          # что вернётся
./venv/bin/python -m app.tools.restore_user --from FILE --user TELEGRAM_ID --apply  # вернуть
```

Дописывается только недостающее; перед записью снимается свежая копия.

В копии нет ключа шифрования паролей — он в `.env`. Храните `.env` отдельно:
без него восстановленная база заставит всех заново пройти `/login`.

### Адрес на yavds

С 08.10.2026 основной `ns.ikrya.ru` направлен прямо на vdsru
(`144.31.222.122`), резервный адрес — `ns2.ikrya.ru`. Описанный ниже
маршрут через yavds сейчас не используется для основного адреса.

Когда мобильный интернет урезают до белых списков, Cloudflare и vdsru не
открываются. Поэтому приложение отдаётся с ВМ yavds в Yandex Cloud: адреса
`https://ns.ikrya.ru` (основной, DNS без Cloudflare) и `https://yavds.ikrya.ru`.
На vdsru `miniapp-mirror@yavds.ikrya.ru` (`deploy/systemd/miniapp-mirror@.service`)
пробрасывает порт 8283 на yavds, там nginx из `deploy/nginx/ns.ikrya.ru.conf` и
`deploy/nginx/yavds.ikrya.ru.conf`. `NETSCHOOL_MIRROR_URL` в `.env` добавляет
кнопку «Резервный адрес» в `/app_reset`.

Кнопка «Войти через Telegram» на главном экране — Telegram Login Widget. Домен
привязывается к боту в @BotFather (`/setdomain`), тот же домен без схемы —
в `NETSCHOOL_TG_LOGIN_DOMAIN` в `.env`. Telegram пускает виджет только с этого
домена, поэтому на зеркалах кнопки нет; пустая переменная её выключает.
Если домен привязан не к основному боту (у бота домен один), токен того бота —
в `NETSCHOOL_TG_LOGIN_BOT_TOKEN`.
Администратор переключает виджет командой бота `/tgwidget main|reserve|off`
(основной бот, резервный, выключить) — без перезапуска.

Приложение отдаётся с корня домена. Старые ссылки `/mini/netschool/...`
переадресуются на те же пути от корня.

### Доступ к школьным серверам через yavds

Часть региональных серверов не принимает соединения с vdsru. Поэтому запросы
к «Сетевому городу» идут через ВМ yavds в Yandex Cloud, при её отказе — через
платный прокси, и только потом напрямую. Текущий режим в `.env`:

```dotenv
NETSCHOOL_PROXY=socks5://127.0.0.1:1082
NETSCHOOL_BACKUP_PROXY=socks5://логин:пароль@хост:порт
NETSCHOOL_FALLBACK_PROXY=off
```

`127.0.0.1:1082` — локальный SOCKS5, который `deploy/systemd/asurso-socks.service`
держит через SSH на `vlad@yavds.ikrya.ru`. Ключ туннеля хранится вне
репозитория в `/root/.ssh/asurso_proxy_ed25519`; на yavds его публичная часть
добавлена в `authorized_keys` с `from="<IP vdsru>",restrict,port-forwarding`.
При смене ВМ yavds нужно обновить ключ хоста в `/root/.ssh/known_hosts` на
vdsru: туннель проверяет его строго.

Запасной маршрут включается, только если прокси не соединился с сервером
школы; ответ сервера (в том числе 403) не повторяется другим путём. Исключения
по хостам — `NETSCHOOL_PROXY_HOSTS=host=` (напрямую) или `host=прокси`.
`NETSCHOOL_FALLBACK_PROXY=off` отключает переход netschoolpy на Tor; общие
переменные прокси окружения не влияют на школьные HTTP-клиенты.

Проверка 14.10.2026 по всем 27 регионам `netschoolpy.REGIONS`: напрямую с
vdsru открываются 15, через платный прокси 25, через yavds 26 (Приморье не
отвечало ни одним путём).

На `/status` отдельно проверяются веб и мобильное API через yavds:
`NETSCHOOL_STATUS_YAVDS_PROXY=socks5://127.0.0.1:1082`. Резервный прокси и
прямой fallback не подменяют отказ этого маршрута. Последний круг хранится
в памяти; после перезапуска таблица ждёт новый круг. На странице показаны
регионы без адресов и названий наших серверов. Графики и проценты относятся
к веб-API. Мобильные адреса (включая порты и пометку отключения) берутся из
каталога ИРТех; ответ 401 без токена означает доступность API, 403 — отказ
в доступе. Работающий веб остаётся доступным при отказе мобильного API.

Прокси относится только к клиенту школьных серверов; соединение бота с
Telegram настраивается отдельно.

### Хранение учётных данных и сессий

Способы входа идут списком: логин и пароль школы, сохранённые данные
(если есть для выбранной школы), QR-код Госуслуг, логин и пароль Госуслуг.
Перед вводом логина и пароля пользователь выбирает, сохранять ли их для
следующих входов. Без согласия эти поля остаются пустыми в базе; сессия
сохраняется для дневника и фоновых уведомлений. После её истечения нужен
новый ручной вход. Старые сохранённые пароли остаются до выхода или нового
входа с отказом от сохранения. Для той же школы доступна кнопка повторного
входа с сохранёнными данными; Госуслуги могут запросить подтверждение.

`/delete_data` и кнопка «Удалить мои данные» требуют подтверждения, затем
останавливают входы и проверки, удаляют пользователя со связанными записями
и серверным календарём CalDAV. Удаление последнего аккаунта не запускает
повторный импорт старых JSON при следующем старте. Удаление не затрагивает
старые резервные копии, сообщения Telegram, локальные копии календаря и
данные на стороне школы; это не гарантированное физическое стирание носителя.

Логи используют статический шаблон операции без динамических параметров и
текста исключений. Файловый лог содержит тип ошибки и позиции в коде без
исходных строк, администратор получает краткое сообщение с тем же номером
события. Новые сообщения приложения должны использовать статический шаблон
и отдельные аргументы, не f-строки с пользовательскими данными.

Сохраняемые пароли и сессии «Сетевого города» шифруются ключом из `.env`.
Копия базы без ключа не раскрывает эти секреты; оценки и прочий кэш остаются
незашифрованными. Владелец сервера с доступом к ключу может расшифровать секреты:

```dotenv
NETSCHOOL_SECRET_KEY=<вывод python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())">
```

При старте открытые пароли и сессии перешифровываются автоматически. Без ключа бот
работает как раньше и пишет предупреждение в лог. Смена ключа:
`NETSCHOOL_SECRET_KEY=новый,старый`, рестарт, затем старый можно убрать.
Потерянный ключ не восстановить — пользователям придётся заново пройти `/login`.

## Уведомления

Изменения оценок, новые задания и пропуски пишутся в очередь `outbox` той же
транзакцией, что и состояние слежения, и отправляются из неё с повторами.
Сбой Telegram откладывает сообщение, а не теряет; в тихие часы очередь копится
и уходит утром. Устаревшее больше двух суток снимается с очереди.

Сводки (включаются в настройках): по понедельникам — за прошлую неделю,
вечером — расписание и задания на следующий учебный день.

Замены и отмены уроков (включаются в настройках): снимок расписания на неделю
вперёд сравнивается с прошлой проверкой; пустой день считается сбоем ответа.

## Приложение

- **«Д/З»**: отметка «выполнено» (общая с кнопками под `/dz` в боте), фильтры
  «Не сделано» и «Прошедшие».
- **Без сети**: установленное приложение показывает последние загруженные
  данные. Service worker работает по принципу «сначала сеть», поэтому
  старая версия не залипает.
- **Итоги**: нажмите учебный год над таблицей, чтобы выбрать прошлый год и
  увидеть класс, оценки за периоды, годовую и итоговую. Архив доступен
  в мобильном режиме для годов, которые возвращает «Сетевой город».
- **Календарь**: меню ☰ → «Расписание в календаре» — отдельный аккаунт CalDAV
  с автоматически обновляемыми уроками. Подписка `.ics` сохранена как альтернативный способ.
- **История оценок** и **статус проверки** — в меню ☰.
- **Вложения заданий без «Сетевого города»**: проверка оценок, увидев задания
  на ближайшие две недели, скачивает их файлы в фоне (по одному, с паузой) в
  `data/attachments` и хранит 14 дней (`NETSCHOOL_KEEP_ATTACHMENTS_DAYS`, 0 —
  выключить). Открытый в приложении файл тоже сохраняется. Файл к заданию
  один на весь класс, а отдаётся только тем, у кого это вложение было в
  заданиях. Сохранённая копия открывается сразу — и когда школьный сервер
  лежит. Файлы больше 25 МБ не хранятся; сверх `NETSCHOOL_KEEP_ATTACHMENTS_MB`
  (3000) удаляются самые старые. Код — `app/attachments/keeper.py`.
  Пока это **бета**: в настройках есть тумблер «Сохранять файлы заданий»
  (по умолчанию выключен), и есть он только у админа. Админ видит второй
  тумблер «Открыть всем» — с ним тумблер появляется у всех (`app_flags`).
  Сохраняются файлы только у тех, кто тумблер включил.

## Статус «Сетевого города»

Публичная страница **https://ns.ikrya.ru/status** (без входа): доступность
серверов «Сетевого города» по всем регионам.

Мониторинг доступности и учёт версий работают отдельно от проверок аккаунтов.
Дополнительно статус показывает обезличенные итоги фоновых проверок дневников
за последние 30 минут: только сервер, пятиминутный интервал и счётчики успехов
и ошибок сервера (`sgo_account_checks`). Ошибки входа не учитываются. После
трёх и более проверок, если больше половины завершились ошибкой, карточка
показывает «Проблемы с дневниками». Эти результаты не меняют график и процент
доступности страницы входа и не объявляют весь регион недоступным.
Бот сам, своим HTTP-клиентом (тем
же маршрутом, что вход: прокси по хосту, сертификаты Минцифры), раз в минуту
ходит на каждый сервер.

Страница статуса (и её экран внутри приложения) получает сигналы об изменениях
через публичный WebSocket `/status/ws`, а снимок — через `/status/data`.
Подключение восстанавливается после обрыва; если WebSocket недоступен,
работает опрос раз в 30 секунд. Открытый период, поиск и раскрытые регионы
сохраняются. «Обновить» запрашивает последний снимок без перезагрузки страницы;
новый круг проверок регионов посетители не запускают.

В шапке миниаппа есть кнопка ↻: она обновляет текущую вкладку на месте.
Ручное обновление обращается к школе даже в первые две минуты после сбоя.
Успешная загрузка снимает старую плашку; профиль, старая копия и запоздавший
ответ мониторинга восстановлением не считаются. Пока плашка открыта, сигналы
статуса позволяют повторить загрузку после восстановления сервера, не чаще
раза в 30 секунд; отдельная кнопка «Проверить снова» доступна сразу.

- **Список серверов** — каталог регионов мобильного приложения NetSchool
  (`mobile.ir-tech.ru`, без входа, обновляется раз в 6 часов) плюс справочник
  `netschoolpy` (там есть Волгоград, которого нет в каталоге). Тестовые серверы
  ИРТех отбрасываются.
- **Сайт** — `/webapi/logindata` без входа: ответил ли и какая версия. 200 без
  JSON — неудача. «Технические работы» — только при явном объявлении в ответе;
  при 503 дополнительно проверяется главная страница. Сам код 500/503 не
  означает техработы (например, 500 бывает у протухшей сессии старого сервера).
- **Мобильное API** — `/api/mobile/users` без токена: 401 значит «отвечает».
  Данных без токена не получить, но так видно, что мобильная часть жива.
- **Пометки ИРТех** из каталога: «регион отключён в приложении» и комментарий
  (например, переход Челябинской области на «Госуслуги Моя школа»).
- Состояние: «Работает», «Медленно» (ответ дольше 5 с), «Сбои», «Недоступен»
  (две неудачи подряд). Сбой — две и больше неудачных проверок подряд.
  Только удачный ответ завершает серию; пауза между опросами не считается
  восстановлением. Время начала берётся из сохранённой истории, а не из
  времени последней удачной проверки личного дневника.
- График за 24 часа / 7 / 30 дней: сколько серверов было недоступно и сколько
  пришло жалоб; у каждого сервера — полоса доступности.
- Версии — своя история в `sgo_status_versions`. Проверки — `sgo_probes`
  (31 день).
- «Сообщить о сбое»: с одного адреса — одна жалоба на сервер за полчаса и не
  больше пяти в час. Текст жалобы видит только админ: при трёх жалобах на
  сервер за полчаса бот пишет ему (не чаще раза в час). Хранятся 90 дней.

- **«Нет данных»** вместо «Недоступен» — у сервера, который ни разу не ответил
  боту (например, закрыт для адресов нашего сервера, а людям открывается).
  Сбоев и полосы доступности у него нет: проверить его мы не можем.

### В приложении

- Школа не ответила на запрос дневника — карточка «Сервер «Сетевого города»
  сейчас не отвечает — попробуйте позже» с кнопкой **«Сообщить, когда
  заработает»** и ссылкой на статус серверов. Показывается по самой неудаче,
  что бы ни говорила страница статуса (она ходит своим путём и может видеть
  сервер иначе). Дневник грузится дольше 8 секунд, а страница статуса
  считает сервер лежащим, — та же карточка ещё до ошибки.
- «Заработал» приходит, только когда у самого подписчика загрузилась
  текущая неделя дневника (тот же запрос, что делает приложение; пробуем не
  чаще раза в 5 минут и только когда отвечает страница входа). Удачные
  проверки других людей не в счёт: в мобильном режиме они часто читают
  только ленту событий, а не журнал.
- **«Статус серверов»** в меню и в карточке открывается экраном внутри
  приложения (`/status?embed=1` в рамке) со стрелкой «назад» в дневник.
- В настройках уведомлений — **«Обновления «Сетевого города»»**: новая версия
  на сервере своего региона.
- Обе подписки (`sgo_alerts`, `app/status/alerts.py`) проверяются раз в 2
  минуты и приходят в Telegram и push на все устройства — даже если обычные
  уведомления в Telegram выключены: человек попросил сам. «Когда заработает» —
  разовая, без ответа сервера снимается через неделю.

Код — `app/status/service.py`, `app/status/alerts.py`, страница —
`app/web/status.py`, `templates/status.html`, `static/status/`, в приложении —
`static/js/sgo.js`.

## Учебные периоды

«Итоги» делятся на четверти, триместры или полугодия. Границы: свои даты из
меню ☰ → «Учебные периоды», иначе настоящие периоды школы из мобильного API,
иначе общепринятые даты. Калькулятор баллов и «что если» считают по одним и
тем же порогам оценок.

## Разработка

Дневник, домашние задания и оценки мини-приложения сохраняются локально
на сервере бота в SQLite. Если сервер школы недоступен (в том числе если
не загрузилась одна из недель), приложение показывает последнюю успешно
сохранённую версию с отметкой об устаревших данных. Устаревший кэш показывается
сразу, пока обновление идёт в фоне; повторные запросы одного раздела используют
одно общее обновление. Ошибка не затирает кэш.
Для раздела, который ещё ни разу не загрузился, сохранённых данных нет.
История уведомлений о заданиях и посещаемости сохраняется даже при
временном исчезновении записей из ответа, поэтому восстановление дневника
не приводит к повторной рассылке уже виденных записей.

```bash
pip install -r requirements-dev.txt
python -m pytest
```

Тесты не ходят в сеть и не требуют базы на диске — база поднимается во
временном каталоге на каждый тест.

## Школьный календарь CalDAV

Radicale встроен в веб-сервер через WSGI: отдельный процесс, порт и сервер
не нужны. Запросы `/caldav/` идут через тот же HTTPS/nginx и туннель, что PWA.
`/.well-known/caldav` перенаправляет на адрес CalDAV; при префиксе приложения
адрес будет `<префикс>/caldav/`. Публичный HTTPS обязателен для подключения
телефонов: Basic Auth передаёт отдельный пароль календаря.

После установки новых зависимостей, обычной миграции и перезапуска бота
функция включена (`NETSCHOOL_CALDAV_ENABLED=true`). Интервал проверки школы —
`NETSCHOOL_CALDAV_INTERVAL=1800` секунд, минимум 300. Отключение не затрагивает
бота и прежние ICS-подписки. При большой очереди пользователей период
увеличивается на время запросов к школе; один запрос ограничен 90 секундами.

Подключение на iPhone:

1. В приложении: ☰ → «Расписание в календаре» → «Создать доступ CalDAV».
2. Сохранить сервер, логин `ns…` и пароль. Пароль показывается только один раз.
3. Настройки → Приложения → Календарь → Учётные записи календаря → Добавить
   учётную запись → Другое → Учётная запись CalDAV.
4. Ввести сервер из приложения, логин и пароль; SSL включён,
   порт 443. Если iOS предлагает расширенные настройки, полный URL указать
   из поля Account URL. При вводе только домена сервер поддерживает обнаружение
   через `/.well-known/caldav` и PROPFIND на `/`. Включить календарь «Школьное расписание».

Бот публикует прошлую неделю и три недели вперёд, сохраняет уже опубликованные
события за последние 30 дней. Телефон читает календарь; запись запрещена.
Данные обновляются в фоне даже без открытого приложения и независимо от
включения уведомлений об оценках. Первый запрос к школе запускается сразу
после создания аккаунта. Экран показывает результат последней проверки;
«Проверить расписание сейчас» запускает повторную проверку без ожидания
периодического цикла. Частоту синхронизации телефона определяет iOS.

UID зависит от школы, ребёнка, даты и номера урока. Замена предмета/кабинета/
времени обновляет прежнее событие, остальные события сохраняют ETag. Полный
снимок заменяется атомарно средствами Radicale: прерванная запись не оставляет
полукалендарь. Если школа недоступна или весь ответ пуст, остаётся последняя
версия. Пустой отдельный день удаляет уроки только после второй успешной
проверки, в которой другие дни содержат уроки. День с некорректным временем
сохраняется до получения полных данных; даты, отсутствующие в ответе школы,
не считаются отменёнными. Это намеренная задержка отмены целого дня ради
защиты от неполных школьных ответов.

В базе — только SHA-256 хэш случайного 256-битного пароля календаря. Этот пароль
не даёт доступа к API приложения или школьному аккаунту. «Выпустить новый
пароль» отзывает прежний; «Отключить доступ» отзывает только CalDAV; `/logout`
отзывает CalDAV вместе со ссылками приложения. Старые события на телефоне
могут оставаться до удаления календарного аккаунта в настройках iOS.

Файлы Radicale лежат в `data/caldav/`, актуальный снимок — в SQLite в кэше
`caldav`. Для полной копии календарного сервера сохраняйте также `data/caldav/`
при остановленном процессе: обычные резервные копии проекта копируют SQLite.
Если файлы Radicale потеряны, бот пересоздаёт их при следующей успешной
проверке школы из снимка и новых данных. Окончательное испытание на iPhone
после выкладки должно включать обнаружение календаря, одну замену, отмену,
смену пароля и повторную синхронизацию.

### Защита входа в веб-приложение

В меню приложения → «Защита входа» можно задать PIN из четырёх цифр, затем зарегистрировать системный ключ доступа. На iPhone
он подтверждается Face ID/Touch ID или кодом устройства. В Telegram используется
встроенный BiometricManager (версия 7.2+): случайный секрет хранится в нативном
биометрическом хранилище, на сервере — только его хэш. Биометрия миниаппа
включается и выключается отдельным тумблером для текущего устройства; его
название выбирается по фактическому типу Telegram: Face ID/Touch ID на Apple,
распознавание лица/отпечаток на остальных устройствах. При выключении секрет
отзывается на сервере. Passkey внутри Telegram не используется. Если устройство
не поддерживает биометрию, остаётся вход по PIN. В Safari/Chrome используются
ключи доступа WebAuthn. Биометрия требует HTTPS и настраивается отдельно для каждого
домена приложения. PIN действует на всех устройствах; дневник блокируется
при открытии и возвращении из фона. Тумблер «Запрашивать PIN в Telegram»
позволяет убрать дополнительную блокировку в миниаппе, сохранив её в браузере.
Этот режим действует только для входа с проверенной сервером подписью Telegram;
неподписанная ссылка по-прежнему требует PIN. API проверяет разблокировку на сервере,
PIN хранится как salted scrypt hash, секрет разблокировки — только в памяти
страницы. Для входа без сети устройство хранит PBKDF2-хеш PIN с солью. После
10 ошибок подряд сервер перестаёт принимать PIN до входа по биометрии или
сброса защиты.
Если PIN забыт, команда `/resetpin` в личном чате с ботом сбрасывает
PIN, ключи доступа и сессии разблокировки.

Школьная почта проверяется при каждом фоновом проходе независимо от ленты
оценок. Первый успешный запрос создаёт тихую базовую сверку; последующие новые
ID писем попадают в очередь при включённой настройке «Школьная почта».
Тихие часы и неудачная доставка откладывают уведомление. Прочтение письма
не мешает уведомлению о его появлении.


Новый код блокировки — ровно четыре цифры (включая начальные нули).
Пинпад подтверждает ввод автоматически после четвёртой цифры; при задании
нужно повторить код. Ранее установленные пароли продолжают работать для
первого входа: после подтверждения приложение предлагает заменить их на PIN.
В браузере «Вход по Touch ID / Face ID» — тумблер регистрации/отзыва Passkey
для текущего домена; окончательный способ проверки выбирает устройство.
