# Задача для агента: доделать мобильное API в netschoolbot

## Контекст

Проект `netschoolbot` (`/opt/netschoolbot` на сервере `vdsru.ikrya.ru`, репозиторий
`git.dc09.xyz/ikrya/netschoolbot`, ветка `main`) — Telegram-бот и мини-приложение
для «Сетевого города». Библиотека доступа — `netschoolpy`
(`git.dc09.xyz/ikrya/netschoolpy`, локальный чекаут `~/netschoolpy`), она же на PyPI.

В netschoolpy 9.0.0 уже есть клиент **`MobileNetSchool`** — доступ к API приложения
NetSchool (`/api/mobile/*`, Bearer-токен `identity.ir-tech.ru` на 60 дней). Полная
карта маршрутов и форматов ответов — в `docs/mobile-api-observed.md`. Бот умеет
переключаться между веб-API и мобильным (`/changeapi`, поле `users.api_mode`,
`User.effective_api_mode`). Секрет приложения на сервере лежит в
`/opt/netschoolbot/.env` как `NETSCHOOL_MOBILE_CLIENT_SECRET`; в код и репозитории
его не добавлять.

Предыдущий агент реализовал переключение режимов и вывод времени публикации ДЗ, но
не смог доделать шесть задач ниже — на них срабатывал внешний фильтр контента.
Никаких технических препятствий в коде нет: задачи — обычная работа с уже
задокументированным API. Реализуй их аккуратно, с тестами.

## Общие правила

- Тесты гоняй командой из `pytest.ini`, `asyncio_mode=auto`. Локально `tests/test_web.py`
  требует пакет `aiohttp_jinja2` — поставь его в venv, если не стоит.
- HTTP к серверам мокай через `httpx.MockTransport` (как в `tests/test_mobile.py`
  у netschoolpy и `tests/test_api_mode.py` у бота). Живые запросы к
  `sgo.e-mordovia.ru`/`ir-tech.ru` в тестах не делай.
- Веб-режим (`ApiMode.WEB`) не ломай: все новые возможности — только для
  `effective_api_mode is ApiMode.MOBILE`, с аккуратным поведением, когда данных нет.
- Изменения в библиотеке (`~/netschoolpy`) и в боте — отдельными коммитами в свои
  репозитории. Библиотеку версионируй как 9.1.0.
- Формат коммитов — как в истории (заголовок в повелительном наклонении, тело
  по-русски, в конце строка `Co-Authored-By: ...`).
- Каждую задачу доводи до конца: код → тесты → коммит. Затем деплой (см. «Выкладка»).

## Задача 1. Быстрая проверка оценок и ДЗ через period-events

Сейчас `UserWatcher._check` (`app/notifications/watcher.py`) каждый цикл тянет через
`DiaryService.fetch_marks`/`fetch_homework` дневник за ~10 недель. У мобильного API
есть лёгкая лента: `MobileNetSchool.period_events(period_days=…)` возвращает
`{events: [{type: "ResultInfo"|"HomeworkInfo", result?, homework?}], ...}` — только
свежие оценки и задания.

- Добавь в `DiaryService` метод, который в мобильном режиме отдаёт свежие события
  через `period_events` (например `fetch_recent_events`), а в веб-режиме — прежний
  путь. Помести решение о режиме в сервис/пул, а не в watcher.
- Для мобильного режима watcher должен по этим событиям формировать те же
  `MarkEvent`/`HomeworkRecord`, что и сейчас, чтобы `diff.py` и уведомления работали
  без изменений. Полную выкачку дневника оставь как запасной путь (например, если
  событий нет или пришла ошибка).
- Учти `PeriodDays`: приложение шлёт `14` и `1`. Не потеряй оценки, выставленные
  задним числом, — тут поможет запас по дням.
- Тесты: мок `MobileClient`, отдающий события; проверь, что новая оценка и новое ДЗ
  превращаются в уведомления, а веб-режим ходит прежним путём.

## Задача 2. Средний балл класса и аналитика по предмету

`MobileNetSchool.subject_performance(subject_id, term_id)` возвращает `averageMark`,
`classAverageMark`, `markStats` (распределение оценок), `attendance`,
`classmeetingsStats`. Экран «Итоги по предмету» в мини-приложении
(`app/web/static/js/totals.js`, эндпоинт `/api/marks` в `app/web/api.py`) сейчас
показывает только средний балл ученика.

- В мобильном режиме добавь в ответ `/api/marks` (или отдельный эндпоинт
  `/api/subject/{id}`) средний балл класса и статистику. `subjectId`/`termId` бери
  из мобильных `subjects`/`terms`.
- На экране покажи строку «у класса X,XX» рядом со средним ученика. В веб-режиме,
  где этих данных нет, строку не показывай.
- Тесты: эндпоинт отдаёт `class_average`, когда данные есть, и не падает, когда нет.

## Задача 3. Итоговые оценки одним запросом

Веб-режим тянет итоговые оценки медленным отчётом через SignalR. У мобильного API
есть `MobileNetSchool.totals(school_year_id)` — четвертные и годовые по всем
предметам одним запросом (`termTotals`, `yearTotals`).

- В мобильном режиме источником итоговой таблицы («предмет × четверть» +
  годовая/итоговая) сделай `totals`. Сопоставь коды периодов из `terms` с
  колонками таблицы.
- Веб-режим не трогай.
- Тесты: из мок-ответа `totals` собирается таблица с четвертными и годовой оценками.

## Задача 4. Учитель, кабинет и тема урока без лишних запросов

В мобильном режиме уроки (`classmeetings`) уже содержат учителя, кабинет и тему,
и `MobileNetSchool.diary()` кладёт их в модель (`Lesson.teacher/room/topic`).
Функция `_teachers` в `app/web/api.py` при этом всё равно делает отдельный запрос
на учителя по каждому предмету (нужный только для веб-режима, где в дневнике
учителя нет).

- В мобильном режиме пропускай `_teachers` и `fetch_teachers` — учитель уже в уроке.
- Убедись, что кабинет и тема доезжают до экранов «День»/«Итоги».
- Тесты: в мобильном режиме `fetch_teachers` не вызывается, а учитель в JSON есть.

## Задача 5. Посещаемость

В уроках мобильного API есть `attendance` (например `"Б"`), а
`subject_performance` отдаёт `attendance` по датам. `Lesson.absence` уже
прокидывается в мини-приложение.

- Добавь сводку пропусков за период (по предметам) — эндпоинт для мини-приложения
  и/или строка в «Итогах по предмету».
- Добавь тип уведомления «новый пропуск»: в `NotificationPrefs` новый флаг
  (`absences`, по умолчанию выкл.), миграция БД по образцу существующих,
  сохранение/загрузка в `UserRepository`, тумблер в настройках и обработка в
  watcher по аналогии с оценками (нужно состояние «уже виденные пропуски», чтобы
  не слать повторно). Только для мобильного режима, где данные о пропусках есть.
- Тесты: разбор `attendance`, формирование сводки, срабатывание уведомления один раз.

## Задача 6. Предупреждение об истечении токена

`MobileToken` живёт 60 дней и содержит `expires_at`; есть `MobileToken.expires_soon()`.
Сейчас по истечении бот в мобильном режиме просто отдаёт ошибку авторизации.

- Пусть бот заранее (например, за 3 дня) предупреждал пользователя в личке:
  «мобильный доступ скоро истечёт, войдите заново: /login». Слать один раз, не
  каждый цикл (нужен флаг/отметка времени, чтобы не спамить).
- Идеально — попробовать продлить токен автоматически через
  `MobileNetSchool.refresh()` (`refresh_token`), и предупреждать только если продлить
  не вышло. Учти: продление может аннулировать refresh-токен на телефоне пользователя;
  прими это как ожидаемое и отрази в тексте/доке.
- Тесты: у почти истёкшего токена предупреждение уходит один раз; при успешном
  refresh срок продлевается и предупреждение не шлётся.

## Отдельно: вход через Госуслуги в мобильное API (со звёздочкой)

Сейчас для входа через Госуслуги мобильный режим намеренно выключен
(`User.mobile_api_supported`), потому что после перезапуска бота ESIA-сессия не
восстанавливается, а мобильный токен из неё не переполучается.

Правильное решение: при живой веб-сессии Госуслуг получать мобильный токен тем же
способом, что и для пароля, — через `NetSchool.mobile_token()` (одноразовый код из
`/webapi/mysettings/mobile/pincode` → `identity.ir-tech.ru/connect/token`). Токен
живёт 60 дней и ESIA-сессию дальше держать не нужно. Если это заработает надёжно —
сними ограничение `mobile_api_supported` для Госуслуг и дай им мобильный режим.
Если надёжно не выходит — оставь текущее защитное поведение (веб-API) и опиши,
почему. Не убирай защиту, не заменив её рабочим входом: пользователь не должен
застревать в цикле «войдите заново».

## Выкладка (после каждой задачи или пачкой)

1. Библиотека: коммит в `~/netschoolpy`, `git push origin main` (это dc09).
   PyPI-публикация из CI dc09 сейчас падает — не полагайся на неё. На сервер ставь
   так: собери wheel из нужного коммита (`python -m build --wheel`), скопируй на
   `vdsru.ikrya.ru` через `scp`, поставь `pip install --no-deps --no-index <wheel>`.
2. Бот: коммит в `/Users/vladislav/netschoolbot`, `git push dc09 main`.
   `github.com/vkrya/*` недоступен — аккаунт заблокирован, туда не пушить.
3. Деплой на сервер (SSH `root@vdsru.ikrya.ru`):
   `cd /opt/netschoolbot && git fetch -q origin main && git reset -q --hard origin/main`,
   поставить новую netschoolpy (см. п.1), при изменении статики мини-приложения
   сбросить кэш (`delete from cache_entries where section in (...)`),
   `systemctl restart netschoolbot`, затем `systemctl is-active netschoolbot` и
   проверить `journalctl -u netschoolbot` на отсутствие ERROR/Traceback.
4. Перед деплоем делай копию БД:
   `venv/bin/python -c "import sqlite3;a=sqlite3.connect('data/netschoolbot.sqlite3');b=sqlite3.connect('data/netschoolbot.sqlite3.bak-'+__import__('datetime').datetime.now().strftime('%Y%m%d-%H%M%S'));a.backup(b)"`.
