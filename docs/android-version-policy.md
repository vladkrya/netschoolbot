# Отключение конкретной сборки Android

В админке сайта, раздел «Android-приложение», владелец указывает числовой
`versionCode` и нажимает «Потребовать обновление этой сборки». Отключаются
только выбранные номера; «Разрешить снова» снимает ограничение.

- `GET /android/policy.json` публично возвращает `packageName` и
  `blockedVersionCodes`, всегда с `Cache-Control: no-store`.
- `POST /api/admin/android-version`, JSON `{"versionCode":5,"blocked":true}`:
  доступ только владельцу, как у остальных админ-настроек. `blocked:false`
  разрешает сборку снова. API учитывает обычный префикс мини-приложения.
- Состояние сохраняется в БД через `app_flags` с ключами
  `android_version_blocked:<versionCode>`. Новая миграция не нужна.
- Нельзя заблокировать последнюю или более новую сборку, заблокировать
  что-либо без опубликованного нового APK или при выключенном канале.
  Пока есть блокировки, выключение канала через админку отклоняется.
  Проверка и изменение сериализованы общим lock, чтобы параллельные запросы
  блокировки версии и выключения канала не оставили пользователя без обновления.
- Снятие блокировки доступно и при отсутствии APK/выключенном канале —
  в том числе для восстановления после ручного изменения файлов/БД.
- Скачивание заблокированного APK через публичный маршрут возвращает 410.
  Последняя актуальная сборка остаётся доступной через обычный канал.

Нужен APK с клиентской поддержкой политики (начиная с Android 0.5.0).
Установленная 0.4.0 не содержит этой проверки, её новый список не отключает.
Клиент сохраняет успешно полученную политику и требует обновление также
без сети; серверное снятие ограничения применится после успешной проверки.
Приложение проверяет политику при открытии и раз в минуту на экране;
закрытое приложение не получает мгновенного сигнала.

Серверная реализация проверена полным набором: 1348 тестов прошли.
Развёртывание сервера и публикация подписанного APK — отдельные действия;
наличие этого файла не подтверждает их выполнение.

Имена новых сборок: `sgoshka-v.<versionName>.apk` на основном домене
sgoshka.ru. Метаданные отдельной версии сохраняются как
`sgoshka-v.<versionName>.json` и `sgoshka-<versionCode>.json`: это связывает
публичное имя с числовым номером блокировки даже после выхода следующих APK.
Для старых установок на прежнем домене сохранён прежний манифест с
`sgoshka-<versionCode>.apk`; оба адреса проверяют одну и ту же блокировку.
