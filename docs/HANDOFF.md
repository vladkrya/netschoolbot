## Где ты работаешь

Ты в облаке, в свежем клоне с GitHub. Ветка с работой — `wip/attachment-page`
(в ней же этот файл и два незадеплоенных коммита). Чего у тебя НЕТ:
SSH к проду, `.env` с секретами, локальной памяти прошлой сессии, браузерного превью.
Поэтому: ничего не деплой и не ходи на сервер — только код, тесты, коммиты в эту ветку
(или новую от неё) и, если просят, PR в `main`. Проверку на проде и деплой сделает
пользователь (или локальная сессия) после твоего отчёта.

Запуск тестов: `python -m venv venv && ./venv/bin/pip install -r requirements.txt pytest`
и `./venv/bin/pytest -q` (netschoolpy==9.4.3 ставится из PyPI). Локальный веб без бота:
`NETSCHOOL_BOT_TOKEN=1:local NETSCHOOL_DATA_DIR=/tmp/nsdata NETSCHOOL_PUBLIC_URL=http://127.0.0.1:8283 TELEGRAM_LOGGING_ENABLED=false ./venv/bin/python -m app.main --no-bot`.
Реальный «Сетевой город» из облака не дёргай — нет учётных данных; пиши тесты с заглушками.

## Правила (обязательно)

- **Никогда не пушь в `main` и не мержи PR сам.** Пуш в `main` запускает автодеплой на прод
  (CI → ветка deploy → таймер на сервере раз в минуту). Работай в своей ветке.
  Ручной деплой: `deploy/deploy.sh` (тесты → dc09 → remote-deploy.sh с бэкапом и откатом).
- Перед деплоем проверь `git status` на проде (`root@vdsru.ikrya.ru:/opt/netschoolbot`).
  Ожидаемо неотслеживаемые: `app/web/static/js/offline.js`, `tests/js/`. Другое — спроси.
- Живые проверки «Сетевого города» — только на аккаунте пользователя СоловьёвВ2
  (telegram 1588860201, он же админ). Чужие аккаунты не трогать.
- Не вводить PIN и пароли пользователя. Не повторять в чате токены, билеты на вложения,
  сгенерированные тестовые пароли — они дают доступ к аккаунту.
- `~/netschoolpy` не править — там чужие незакоммиченные правки.
- Тесты: `pytest -q` (сейчас 857 зелёных). Не проверяй результат через `pytest | tail` с `&&` —
  код выхода теряется; используй `set -o pipefail` или смотри вывод.

## Задача 2 — версии «Сетевого города» в логах

Пользователь: «учитывай тоже версии сетевого города в логах». Сейчас версию никто не
записывает (Мордовия сейчас 5.58.7, Забайкалье 5.58.7, какая была до простоя — неизвестно).
Идея: брать версию из `GET {school}/webapi/logindata` (поле версии), хранить по хосту
(лучше в БД — новая миграция 27, таблица `sgo_versions(host, version, seen_at)`),
логировать смену версии и слать админу сообщение «⚠️ хост X: 5.58.6 → 5.58.7».
Удобно встроить рядом с `app/notifications/outage.py` (`OutageMonitor`, считает
проверки по хосту) — например, проверять версию при восстановлении после простоя
и раз в N часов. Сообщения админу — через тот же `send`, что у OutageMonitor.
